# Контекст AL Torrent Tools

## Назначение и структура
- Сервис автоматизации AniLibria/AniLiberty: синхронизация релизов, архив `.torrent`, qBittorrent master → slave, история файлов, контроль AVC/HEVC, Telegram и отправка в Video Kensetsu.
- Рабочий Python-код находится в `backend/`. Корневой `app/` содержит пустые пакеты: запускай приложение и тесты из `backend/`, чтобы не импортировать их вместо рабочего кода.
- Стек: обычный CPython 3.15 (README и Dockerfile), FastAPI, синхронный SQLAlchemy, PostgreSQL 16/psycopg, Alembic, APScheduler, httpx, qbittorrent-api, python-telegram-bot, BLAKE3, pymediainfo. Версии Python-зависимостей закреплены в `backend/constraints.txt`; t/JIT не включены.
- UI: Jinja2 + HTMX + JavaScript/CSS в шаблонах; отдельного frontend build/package.json нет. Основной шаблон — `backend/app/templates/base.html`, фрагменты — `templates/partials/`.
- `README.md` описывает запуск и Unraid; `docs/PROJECT_PLAN.md` — текущую архитектуру (историческое имя сохранено); `docs/MULTITASK_PROMPTS.md` — архив первоначальных заданий. При расхождениях сверяй код и тесты.

## Где искать реализацию
- `backend/app/main.py`: HTML-страницы, формы, HTMX partials, SSE `/ui/events`, health и lifecycle приложения.
- `backend/app/api/rest.py`: REST `/api`, webhook qB, создание общего `job_runner` и регистрация обработчиков джобов.
- `backend/worker.py`: расписание APScheduler, fallback polling pipeline, retry waiting master/slave, reclaim зависших джобов.
- `backend/app/jobs/`: сценарии ongoing/full_sync/meta_sync, reconcile/resume, cleanup, hashing и MediaInfo. `services/job_catalog.py` — каталог джобов и описание расписаний.
- `backend/app/services/job_runner.py`: состояния джобов, дедупликация, PostgreSQL advisory locks, кооперативная остановка. Ручные и scheduled джобы используют `schedule_job`: немедленная отправка в ограниченный пул потоков своего процесса, своя Session и event loop. Worker не является общей очередью для всех запусков. Родительский loop не владеет executor дочерних hash jobs и не ждёт их при закрытии; отмена wrapper не отменяет dispatch, остановка — через БД.
- `backend/app/providers/anilibria/client.py`: API-клиент; `services/runtime_settings.py`: DB overrides; `services/release_checkpoint.py`: маркеры обновлений и fingerprint для пропуска неизменившихся релизов.
- `providers/anilibria/backoffice.py`: Nova, только GET данных и POST `/login`; общие сохранённые логин/пароль AniLiberty. `sources.py`: site имеет приоритет, кроме hidden/copyright-blocked (geo сам по себе остаётся site); ID релизов/торрентов общие. Подтверждённый public 404 разрешает импорт geo-only из Nova; сетевой сбой не разрешает новый переход. `jobs/backoffice_sync.py`: полный discovery раз в 900 с по умолчанию, включая возвраты на сайт; interval настраивается отдельно. Discovery начинается с полного индекса Nova; публичный каталог — только необязательное ускорение с общим лимитом 30 с и полной проверкой пагинации. При его сбое остаётся полный Nova-обход; watched-релизы никогда не исключаются подсказкой. Публичный hint исключает только явные copyright=false и geo=false (Nova-only is_hidden может отсутствовать); явные Nova geo-кандидаты не исключаются без проверки карточки. Прогресс страниц и обработки виден в info-логах. `full_sync` выполняет этот этап и после ошибки публичного каталога, сохраняя ошибку и запрет глобального sweep; `force_qb_load` передаётся обоим этапам.
- `services/backoffice_torrent_cache.py` / таблица `backoffice_torrent_cache` (0029): detail-кэш только для `backoffice_sync`, свежий полный Nova torrent index читается всегда. Отпечаток — upload stamp, title/description/size/ID и optional hash; реальный index hash не отдаёт, `updated_at` означает загрузку. Попадания не продлевают 6-часовой срок обязательной проверки. Новые/изменённые/неполные записи читаются полностью; расхождение index/detail инвалидирует старый cache. Не подменять этим кэшем архив, checkpoints, api_present, baseline или sticky/SLA; source/qB repair выполняется и при всех cache hits.
- `services/release_source.py` / `torrent_policy.py`: reserved qB tags site/hidden/blocked, полный список трекеров админки с passkey из настроек. Raw info/hash, раздачи и файлы сохраняются; после возврата на сайт backoffice_trackers остаётся для того же hash. Не удаляй пользовательские метки при синхронизации жанров.
- `services/ongoing_watch.py` и таблица `ongoing_watch`: донаблюдение в каждом запуске `ongoing` на 14 дней после первого отсутствия в валидном расписании. Любой новый инкрементальный ID торрента продлевает срок; известный ID — нет. Не удалять архив/pipeline при expiry/404; 404 подтверждать запросом самого релиза. `ongoing` всегда читает список торрентов независимо от markers, передаёт его в processor через `prefetched_torrents`.
- `backend/app/services/torrent_processor.py`: обработка релизов и торрентов; `torrent_archive.py`: архивирование; `qbittorrent.py` и `torrent_qb_meta.py`: взаимодействие с qB и его метаданные.
- `backend/app/services/pipeline.py`: переходы master → slave и аудит; `qb_inventory.py`, `file_tracker.py`, `file_hasher.py`, `torrent_files_meta.py`: состав, наличие и хеши файлов.
- `backend/app/services/hevc_pairing.py`: правила соответствия AVC/HEVC и SLA; `releases_view.py`: данные страницы релизов. Перед изменениями pairing читай docstring модуля и `test_hevc*`.
- `worker._sync_hevc_overdue` проверяет SLA каждые 60 с независимо от checkpoints. `jobs/hash_torrent.py` ставит в HEVC-outbox уведомление о первом AVC релиза после проверки всех выбранных файлов; дедупликация — по релизу/одобренному чату, с учётом истории архива.
- Pure `missing` после 24 ч имеет отдельное HEVC-уведомление (не смену UI-статуса), только если самое раннее `torrent_archive.created_at` релиза >= 2026-09-30 17:00 UTC (1 октября по Новосибирску); дедупликация по релизу/чату. Старые релизы с новыми версиями не включать.
- Первоначальный импорт админки сохраняет `notification_baseline` в архиве и подавляет HEVC-уведомления, включая отложенное хеширование; расчёт HEVC остаётся активным. Новые AVC после baseline работают по обычным правилам. Расширение импорта на geo-only имеет отдельные `backoffice_geo_baseline_started_at/completed_at`: первый импорт неизвестных geo-релизов подавляет уведомления, старый hidden/copyright baseline не сбрасывается.
- `backend/app/services/mediainfo.py`, `matroska_attachments.py`, `video_kensetsu.py`: метаданные медиа, вложения Matroska и клиент внешнего энкодера.
- `services/encoder_history.py` хранит приём отправки; `encoder_tracking.py`/`encoder_jobs` отдельно наблюдают выполнение и доступность результата. Worker опрашивает GET статуса (30 с active / 300 с terminal), готовность берёт из output_available, legacy — HEAD download. Lease/token и backoff сохраняются; ошибки проверки не становятся ошибкой кодирования. Миграция 0027 восстанавливает только доказуемые legacy single-квитанции и не повторяет POST. Путь и сервер берутся из snapshot; статус Kensetsu не изменяет sticky ui_status/pipeline/HEVC.
- `backend/app/telegram_bot/`: два профиля бота, основной и `hevc`; `services/telegram_access.py`, `telegram_notify.py`, `telegram_outbox.py`, `hevc_notifications.py`: доступ, подписки и уведомления. Корневой `telegram-bot/` содержит только пояснение.
- `backend/app/db/models.py`: модели; `backend/alembic/versions/`: миграции. Архив, pipeline, файлы, disk hashes, checkpoints, job logs, pipeline events и Telegram outbox — разные сущности, не взаимозаменяемые состояния.

## Инварианты при изменениях
- API админки использует отдельный `anilibria_admin_base_url` / `ANILIBRIA_ADMIN_BASE_URL`, один адрес без fallback. Шаблон `anilibria_admin_url_template` отвечает только за ссылки. В публичном каталоге `limit` не больше 50.
- В Nova `is_blocked_by_geo` — `multiselect-field`: null/пустой список = нет геоблокировки, непустой список стран = есть. Не валидируй его как boolean-field; геоблокировка сама по себе не меняет источник при доступной публичной карточке. Nova geo-only допускается после подтверждённого public 404. Политика backoffice применяется и при пустом списке source tags: это снимает старые reserved tags и ремонтирует трекеры, сохраняя пользовательские метки.
- Жанры Nova: `genres.value` содержит ID, `genres.options` — названия. Состав: GET `anime-releases-releasesMembers` через связь `members` релиза, ID участников — UUID; отображаемый ник в text `ComputedField`, роль в select `role`. Не превращай ошибку/неполную пагинацию в пустые метаданные. Подтверждённые пустые жанры админки снимают только managed genre tags, сохраняя source/custom tags.
- Прочитай и соблюдай `.cursor/rules/sticky-file-status-history.mdc`: `ui_status` — история конкретной версии торрента, не текущее наличие файла на диске. Первый торрент целиком `new`; хеширование не превращает его в `ok`. Prior сравнивается по exact `relative_path`; `checking` — временный оверлей.
- Основной pipeline: `discovered → master_added → master_complete → slave_added → done`; недоступность qB обрабатывается через waiting/retry. `slave_added` ещё не означает завершение загрузки на slave.
- Webhook, polling и reconcile могут конкурировать: сохраняй атомарные claims, идемпотентность и PipelineEvent-аудит. Возобновление qb-missing `cancelled` имеет отдельный сценарий и grace-период.
- Не смешивай `api_present`, `superseded`, состояние pipeline и наличие медиа на диске. Исторические архивы нужны для diff файлов и HEVC timeline.
- `api_present` относится к выбранному источнику; public sweep не снимает backoffice-архивы. Retry проверяет точные ID+hash в полном списке источника, а не существование soft-deleted карточки. `release_lock.py` защищает processor одного release_id между джобами; `process_release` и публичный `refresh_release_meta` применяют source policy под одним общим контекстом, внутренний metadata-helper повторно lock не берёт.
- `releases.is_abandoned` — только ручная локальная пометка и фильтр web; синхронизация и HEVC её не учитывают. Для offsite-релизов оба TG-профиля показывают «Нет на сайте» без ссылки на сайт, сохраняя кнопку админки.
- Live UI использует EventSource и HTMX partials. HTMX 1.9.12 хранится локально в `static/vendor/` с лицензией и provenance. `services/ui_events.py` проверяет change tokens каждые 3 с в threadpool, закрывая Session до SSE yield; releases/workbench имеют минутный tick для HEVC SLA. Master/slave polling worker выполняется в отдельных потоках со своими Session. При изменении отображаемых данных проверяй token и partial, сохранение раскрытий, выбора, параметров заданий, фокуса и прокрутки непосредственно перед swap. Медленный запрос не должен дублироваться; HTTP error HTMX 1.x может резолвить Promise и требует проверки события ошибки.
- Для настроек, поддерживающих DB override, используй существующие runtime-resolver'ы: БД имеет приоритет над env/default. Не обходи маскирование секретов и `logging_filters.py`; не сохраняй значения `.env` в заметках.
- Даты БД — naive UTC: используй `app.utils.datetime_fmt.utcnow()` и `as_utc_iso()` при отдаче браузеру.
- `.torrent` хранится через канонический storage resolver (`TORRENT_STORAGE_DIR`); локальный default — `data/torrents` в корне, Docker — `/app/data/torrents`. Медиа — отдельный `ANILIBRIA_MEDIA_ROOT` (default `/anilibria`); сохраняй проверки границ пути и неполных файлов.
- Cleanup по расписанию запускается с `dry_run=True`. Сохраняй раздельные master/slave параметры и существующие ограничения удаления.
- Изменение схемы требует Alembic-миграции. Docker entrypoint сериализует `alembic upgrade head` PostgreSQL advisory lock, поскольку несколько сервисов стартуют одновременно.

## Запуск и проверка
- Из `backend/`: установить `pip install -c constraints.txt -r requirements-dev.txt` в новой venv CPython 3.15 (только runtime — `requirements.txt`); конфигурация — `.env.example` → локальный `.env`; применить `alembic upgrade head` к выбранной dev-БД; API — `uvicorn app.main:app --reload`; worker — `python worker.py`.
- Боты из `backend/`: `python -m app.telegram_bot` и `python -m app.telegram_bot --profile hevc`. Compose поднимает PostgreSQL, API, worker и оба профиля; образ общий, build context — `backend/`.
- Проверки из `backend/`: `python -m pytest -q`; синтаксис — `python -m compileall -q app tests worker.py`. Для изменения поведения выбирай соответствующие существующие `tests/test_*.py` и регрессии на границах сценария.
- Большинство тестов изолируют БД/qB/HTTP mock-объектами; наличие `e2e` в имени не означает проверку реального стека. PostgreSQL-тест миграции 0018 требует `ALTT_TEST_POSTGRES_URL` отдельной тестовой БД.
- Docker требует MediaInfo >=26 и удаляет bundled lib из pymediainfo wheel; MIME вложений читается собственным EBML-парсером. Не убирай эти проверки при изменении образа.
- Docker публикует target `runtime`; локальный Compose использует `development` с pytest/watchfiles. Нативный `_decimal` вручную не собирается; стандартный Python fallback проверен. Uvicorn сохраняет uvloop/httptools; YAML/WebSocket extras приложению не нужны.
- Срез знакомства 2026-10-08, HEAD `f513ff1`: на доступном Python 3.13.2 — 770 passed, 1 skipped (нет `ALTT_TEST_POSTGRES_URL`). Python 3.14, Docker и реальные внешние сервисы в этой проверке не запускались; это исходный результат, не гарантия для будущих изменений.

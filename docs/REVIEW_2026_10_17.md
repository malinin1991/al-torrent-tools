## Разработчик

- **P1 — очистка могла выполняться на неверном клиенте.** `cleanup_slave` с `target_role=master` запускал master-очистку под блокировкой другого типа. Несовпадение отклоняется с HTTP 422 до создания джоба; legacy `cleanup` нормализуется в `cleanup_master`.
- **P2 — недоказанное отсутствие торрента.** Сбой основного API и 404 резервного превращались в `torrent_exists=False`. Теперь `get_torrent` возвращает отсутствие только по `AniLibriaNotFoundError`, то есть подтверждённым 404; смешанные 503/401/ошибка JSON и fallback 404 остаются ошибкой проверки.
- **P2 — round trip настроек портил секреты.** GET маскировал пароль/токен как `***`, а PUT сохранял эту маску. Пустое значение и маска сохраняют прежний секрет и не создают override над env.
- **P2 — проверка qB игнорировала сохранённый порт.** Отсутствующий в запросе порт теперь читается из настроек; явное значение имеет приоритет. Диапазон 1–65535 проверяется и для payload, и для сохранённого значения; некорректная настройка даёт 422.
- **P2 — запрос каталога нарушал лимит публичного API.** `catalog_releases` ограничивает `limit` диапазоном 1–50.

## Архитектор и независимое техническое ревью

- **P1 — терялись вложенные hash jobs.** `schedule_job` откладывал сам dispatch до первого тика wrapper; закрытие временного loop могло оставить часть дочерних заданий `pending`. Работа отправляется в executor немедленно; wrapper использует shield, контекст переносится через `copy_context`.
- **P2 — scheduler блокировался синхронными операциями.** Scheduled handlers и master/slave polling выполняли qB/DB/FS работу в общем event loop. Теперь обработка идёт в потоках с собственными Session. Callback APScheduler ждёт своё задание, сохраняя `max_instances`, `coalesce`, дедупликацию и cleanup `dry_run`.
- **Исправление по повторному ревью — родитель не должен ждать дочернее хеширование.** Временный loop не владеет пулом выполнения jobs: используется один ограниченный executor процесса. Родительский job/poll завершается после своей работы, hash продолжает выполнение. Проверены и немедленная отмена wrapper, и очередь с одним worker, и закрытие parent loop при заблокированном ребёнке.
- **P2 — advisory lock мог вернуться в pool вместе с соединением.** После acquire/unlock добавлен commit; неопределённый исход и ошибки инвалидируют соединение перед close. Обработка релиза больше не держит `idle-in-transaction`. Реальная PostgreSQL-регрессия проверяет конфликт владельцев и состояние соединения.
- **P2 — устаревшая готовность Kensetsu возвращалась после ошибки связи.** Последовательность `ready → 404 → connection error` снова показывала старую ссылку. Ответ 404 сбрасывает доступность/размер результата, сохраняя execution snapshot и `done`; готовность возвращается после подтверждённого ответа.

Файлы: [job_runner.py](../backend/app/services/job_runner.py), [worker.py](../backend/worker.py), [release_lock.py](../backend/app/services/release_lock.py), [encoder_tracking.py](../backend/app/services/encoder_tracking.py). Регрессии: `test_job_schedule.py`, `test_worker_job_dispatch.py`, `test_release_lock.py`, `test_encoder_tracking.py`.

## Аналитик

- **P1 — квитанция одного исходника ошибочно подтверждала другой.** В batch A/B два задания для A или неполный именованный список с `created=2` могли подтверждать B. Именованные задания теперь принимают только точно сопоставленные исходники; агрегат не достраивает пропущенную связь.
- **P1 — противоречивые пути скрывались совпавшим полем.** `path`, `input_path` и `filename` проверяются совместно. Совпавший path не скрывает другое имя/путь. Сохранены точные legacy single-квитанции и полные неименованные batch-счётчики без выдуманного соответствия ID файлам.
- **P2 — недостаточные доказательства приёма.** Голый `created:true/false` больше не считается числом исходников; integer-счётчики и single-ответы с job ID поддерживаются. HTTP вне 200/207 не подтверждает приём даже при положительном теле.
- **P2 — кодек из fallback-label терялся.** `x264`/`x265` сравнивались с uppercase-строкой без нормализации токена. Исправлено распознавание независимо от регистра.
- **P2 — HEVC SLA не обновлялся по времени.** Pairing рассчитывался с текущим временем, но token релизов не менялся без изменений БД. Добавлен минутный SLA tick; его наследует рабочий список HEVC.

Файлы: [encoder_history.py](../backend/app/services/encoder_history.py), [torrent_archive.py](../backend/app/services/torrent_archive.py), [ui_events.py](../backend/app/services/ui_events.py). Регрессии: `test_encoder_history.py`, `test_torrent_archive_meta.py`, `test_ui_events.py`.

## Интеграционные исправления

- Синхронный сбор SSE-token вынесен из API event loop в threadpool. Session создаётся внутри потока и закрывается до yield клиенту, поэтому медленный SSE-клиент не удерживает соединение. Ошибка SQL одного канала вызывает rollback до следующего канала.
- Pipeline SSE-каналы принимают только положительные bigint ID; отсекаются Unicode-цифры, переполнение и слишком длинные значения, одинаковые ID нормализуются.
- В Alembic явно указан `path_separator=os`, устранено предупреждение устаревшего разбора пути.
- Обновлены [архитектура](PROJECT_PLAN.md), [README](../README.md) и [AGENTS.md](../AGENTS.md), включая команды клиентских тестов и новые границы исполнения jobs.

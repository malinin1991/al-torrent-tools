# Протокол до измерений (2026-10-13)

Основная серия: baseline/optimized × regular CPython 3.15 / 3.15t GIL-on / 3.15t default GIL-off, 12 rounds. Каждая комбинация занимает каждую позицию дважды (циклические перестановки, обращённый второй блок). Сценарии чередуют прямой/обратный порядок. Все исходные samples/outliers сохраняются. Один отдельный исключённый correctness/warmup sweep для всех комбинаций; результаты обязаны совпадать до timing series.

Первый обязательный этап: actual GET /releases/live?hevc_filter=overdue и целый run_mediainfo_sync(full/changed incremental) на четырёх пользовательских MKV. Дополнительная отдельная серия: generated-many-files (96 собственных настоящих FFmpeg MKV), whole hash_torrent при возможности. Дополнения не заменяют основной результат.

Основной критерий — absolute wall latency median/p95 и paired bootstrap 95% CI (10000 paired resamples, seed315314). Отсутствие регрессии в диагностическом допуске3%: upper CI<=1.03 для median и p95. Ускорение: upper CI<1.00. CI пересекает предел=неопределённо; никаких дополнительных повторов для желаемого вывода. CPU time процесса и peak RSS — вторичные, учитываются отдельно, PostgreSQL CPU/RAM ими не покрываются. Wall включает ожидание PostgreSQL и durable commits. fsync/synchronous_commit не отключаются.

HEVC: 1024 релиза, восемь сценариев AVC/HEVC с историей, файлами и ignored. Реальные SQLAlchemy/PostgreSQL, сортировка, группировка, Jinja, HTTP response. TestClient/ASGI transport без TCP/TLS/browser; lifespan не запускается, чтобы исключить scheduler/внешние сервисы. Первый запрос нового child process сохраняется отдельно от запроса после двух прогревочных запросов. Cold request означает холодный application request/process; диск и БД не объявляются холодными. Import/startup вне request timer, внешняя process wall тоже сохраняется. Production HEVC pool отсутствует, меток cold/hot pool нет.

MediaInfo: реальные native libmediainfo26.10 parse(full=True), чтение файлов, нормализация, PostgreSQL lookup/upsert/logging/commits целой job. Full очищает file_mediainfo, changed incremental сначала создаёт реальные reports, затем меняет только их тестовый DB mtime на -60; сами файлы не изменяются. В timed operation обязателен native_parses=N, updated=N, errors=0 и одинаковый digest результата. Обёртка счётчика вызывает оригинальный native parse. Fixture stale-gate preparation/reset и correctness queries исключены из timer; production cache-gate lookup входит timer. Кэш ОС не сбрасывается, поэтому серия описывает warm file cache. User MKV mounted readonly, идентификация size+mtime; дополнительный digest read1.4GiB не требуется. Generated clips — отдельный набор и отдельные выводы.

Whole hash при включении: actual FileTracker + BLAKE3 reads + native parse + PostgreSQL commits + audit; единственная подмена — внешняя qB inventory (save/content paths, complete progress, selected priorities), полностью детерминированная. Перед запуском очищаются наши DiskFileHash/MediaInfo/composition rows. Обязательны hashed4, gated0, parse4 и sticky new. qB HTTP latency не измеряется.

Runtime contract: общий Linux ARM64 dual image, 46 одинаковых distributions, pure psycopg3.3.6+libpq170011 во всех режимах. Это не production psycopg-binary parity. Фактический GIL проверяется до/после, forced gil=0 не используется. CPU quota/cpuset сохраняются. RSS ru_maxrss may inherit fork/exec floor; /proc VmHWM сохраняется как дополнительный сигнал. Docker Desktop/Linux ARM64 и bind mounts не эквивалентны native Unraid AMD64.

Только изолированный internal network altt-operations-315-20261013, PostgreSQL16, без host ports. Отдельная operations_tests БД для full suites; benchmark использует operations_hevc/operations_media_real/operations_media_generated/operations_hash. Timing только после READY, clean source freeze, full suites и root GO, без параллельных тестов/сборок.

Усиление correctness до timing: HEVC utcnow в harness фиксирован на2026-10-13T00:00:00 UTC до импорта services/main; fixture dates без offset, свежие10h сценарии сохраняются. Сравнивается SHA256 полного HTML body, включая badges/sort/pagination. Production clock/code не изменяются. Ресурсные результаты вторичны, отдельного отказного ресурсного gate нет.

Whole hash seed содержит master_complete TorrentPipeline; hash_progress/hash_done/ui_status PipelineEvents обязательны и входят смысловыми details/transitions в result digest, без ID/дат.

Протокол v2: после пилота root уточнил HTTP boundary. Regex/assertions/SHA256 полного body выполняются ПОСЛЕ остановки timer. Timer включает только TestClient GET → полностью готовый response (реальные route/SQL/ORM/pairing/Jinja). Пилот сохранён отдельно в operation_benchmark_core_pilot_boundary_linux_arm64.json вместе с exact pilot runner; ни один его sample не смешивается с окончательной серией. Новая серия12rounds начинается с собственного excluded correctness sweep. Это исправление границы измерения, не продолжение/выбор повторов по результатам.

Финальный supplement protocol до его samples: отдельная серия generated 96 full/changed incremental + whole hash real 4. Один excluded correctness sweep всех 6 конфигураций, затем фиксированные 12 rounds независимо от стоимости/относительных результатов. Cyclic/reversed порядок даёт каждую позицию ровно 2 раза. Серия не объединяется с core или пилотом. Все native parse/hash counts и pipeline audit checks обязательны. CPU/HWM whole-child вторичны; JobRunner scheduling/claim/status transition wrapper не входит в handler wall. Core runner не изменён во время измерений.

HEVC pool candidate — третья независимая серия, после supplement: baseline=dedup-only optimized-final, optimized=dedup+pool candidate. Candidate не подключён к production. Только actual HEVC HTTP cold-first/warm, 12 rounds × 6 configurations (72 samples), плюс 6 excluded correctness sweeps. Snapshot/JSON thaw/serialization, lazy persistent pool constructor и submit/merge находятся внутри route timer. Predeclared partition policy ceil(release_count/4) → максимум 4 contiguous release tasks; fixture 1024→4×256 во всех modes. pool_state до первого request created_count0, после cold1, после warm1, actual threads1–4, workers4; evidence вне timer. Full HTML SHA и fixed SLA clock идентичны core. Порог/CI/CPU/HWM методика та же; сравнение adoption — pool t-off против dedup regular и pool regular, не только против собственного t-off before. Source manifests различаются и сохраняются отдельно. Candidate tests выполняются после supplement, performance только после их успеха/parent GO.

MediaInfo default-workers candidate — четвёртая независимая серия после HEVC pool и полного test window: baseline=ORIGINAL (sequential incremental1/per-file transactions), optimized=batch+default incremental4 candidate. Это paired before/after полного финального MediaInfo изменения; промежуточный batch+worker1 из core остаётся отдельной серией и не складывается с новым эффектом. Только actual run_mediainfo_sync changed-real4 и changed-generated96, params mode=incremental БЕЗ explicit workers. 12 rounds × 6 configurations × 2 cases (144 samples), 12 excluded correctness sweeps. Wrapper считает parse calls и peak active real MediaInfo.parse calls, всегда вызывая оригинальный native parser; исходные файлы readonly, stale только тестовая DB metadata. Parsing/normalization/DB gating/writes/commits/logging входят wall, подготовка stale metadata вне timer. Source/runtime contract/3% CI методика прежние, CPU/RAM вторичны согласно приоритету latency. Старые core/supplement/pool raws неизменны.
